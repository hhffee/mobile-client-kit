# Ayu Personal для iOS

**Статус: исходники в разработке. IPA не собран. Полный перенос AyuGram не завершён.**

Личный неофициальный клиент на базе Telegram iOS. Это набор исходников и воспроизводимых изменений к закреплённому upstream, а не официальный AyuGram для iOS.

## Что написано

- Настройки → Ayu Personal: переключатели онлайна, набора/записи, прочтения и рекламы.
- Архив текста перед явными серверными удалениями и правками облачных сообщений.
- Просмотр, поиск и очистка архива отдельно для каждого аккаунта.
- Имя Ayu Personal и собственный векторный знак для основной иконки.
- Подготовка сборки arm64 IPA без подписи и без расширений для последующей подписи на устройстве.
- Проверка IPA: структура Payload, архитектура arm64, платформа iOS device, отсутствие шифрования исполняемого файла.

Это описывает написанный код. Компиляция всего клиента, запуск, вход в аккаунт и проверка на iPhone ещё не выполнены. Полный список функций и статусы — в [FEATURES.md](FEATURES.md).

## Что мешает получить готовый IPA сейчас

На текущем компьютере Windows. Для проекта создан приватный GitHub-репозиторий [hhffee/ayupersonal](https://github.com/hhffee/ayupersonal); подготовлены облачные проверки и сборка. Собственные Telegram API-реквизиты нужно добавить в секреты репозитория: [инструкция](START_HERE.md). Полная сборка на macOS ещё не подтверждена. Подпись через GBox не компилирует Swift и не заменяет этот этап.

Для полного клиента нужна именно база Telegram iOS; Android APK и Desktop-приложение не конвертируются в iOS IPA.

## Будущая облачная сборка

Подготовлен `.github/workflows/build-ios.yml`, запускаемый вручную. Он **не запускался**. Он требует:

1. GitHub-репозиторий с этими файлами и разрешёнными Actions.
2. Секреты `TELEGRAM_API_ID`, `TELEGRAM_API_HASH`: свои реквизиты приложения на https://my.telegram.org/apps.
3. macOS runner с **Xcode 27.1**, как у закреплённой версии Telegram. Workflow предлагает `xcode-27`, но наличие именно 27.1 и достаточного места на runner ещё требуется подтвердить. Несовпадение версии останавливает сборку; оно не скрывается флагом override.
4. Необязательные переменные `AYU_BUNDLE_ID`, `APPLE_TEAM_ID`. По умолчанию bundle ID — `org.personal.ayupersonal`. Нулевой Team ID предназначен только для неподписанного артефакта; при подписи нужны реальные идентификаторы из provisioning profile.

Если upstream успешно скомпилируется, workflow загрузит артефакт `AyuPersonal-unsigned-IPA`. Сборка крупного Telegram может потребовать более мощного macOS runner и дополнительного диска. Платный runner самостоятельно не заказывается.

Для доступного macOS-хоста:

```sh
export TELEGRAM_API_ID='свой api_id'
export TELEGRAM_API_HASH='свой api_hash'
python3 scripts/build_macos.py
```

`build_macos.py` скачивает точный commit и его submodules, применяет изменения, вызывает штатный Bazel/Make.py и проверяет итоговый IPA. Результат после успешного запуска: `dist/AyuPersonal-unsigned.ipa`.

## Подпись и установка

После успешной сборки IPA можно передать в GBox и подписать своим сертификатом и подходящим provisioning profile. Совместимость с конкретным сертификатом и GBox пока **не проверена**. Telegram использует App Groups и Keychain Access Groups; профиль, bundle ID и entitlements должны соответствовать друг другу. Если GBox удалит обязательные App Groups, приложение может не запуститься. Обход или ослабление блокировки приложения в исходниках не добавлялись.

В сборке отключены расширения: Share, Widget, Siri и Notification Service. Push-уведомления стороннего клиента отдельно зависят от APNs и push-инфраструктуры. Сертификат, пароль от него и Telegram-сессия в проект не включены.

## Границы функций

Невидимка не гарантирует сокрытия любой активности: сервер видит отправку сообщений, вызовы и другие запросы. Этот вариант управляет явным онлайн-статусом, обычными индикаторами набора и путями прочтения чатов/комментариев. Просмотры историй, канальные счётчики просмотров и live drafts пока отдельно не перекрыты. После изменения настроек перезапусти приложение: уже отправленные запросы отменить нельзя. Другие устройства работают независимо.

Архив сохраняет **текст**, который уже был в локальной базе перед полученным событием. Он не восстанавливает неизвестные устройству сообщения, вложения или секретные чаты; пока не покрывает массовую очистку истории и удаление при заполнении пробелов синхронизации. Официальная база продолжает применять удаления. Снимки помещаются в отдельный архив асинхронно; аварийное завершение может потерять ещё не записанную очередь.

Архив исключён из резервного копирования, на iOS защищён Data Protection, отделён по ID аккаунта. После 8 МБ журнал сокращается до последних записей, не более 2000 и примерно 4 МБ. Очистка кэша Telegram его не удаляет. **Выход из аккаунта пока не очищает архив автоматически**: для удаления используй кнопку очистки до выхода. Удаление самого приложения удаляет его локальные данные.

## Проверки

```powershell
python -m unittest discover -s tests -v
python scripts/verify_overlay.py upstream/Telegram-iOS
```

Первое проверяет конфигурацию и анализатор IPA, второе применяет overlay к чистым снимкам закреплённых файлов. Эти проверки не заменяют компиляцию Swift или тестирование Telegram.

Для независимого архива подготовлена настоящая Swift-проверка с записью на диск, разделением аккаунтов, восстановлением после оборванной JSONL-строки и ограничением размера. Workflow `checks.yml` успешно выполнил её на macOS: [результат](https://github.com/hhffee/ayupersonal/actions/runs/42867782925). Это ещё не проверка полной интеграции с Telegram.

## Источники и лицензии

Функции сверялись с https://docs.ayugram.one/android/, https://docs.ayugram.one/desktop/, https://github.com/AyuGram/AyuGram4A и https://github.com/AyuGram/AyuGramDesktop. Официальная документация указывает отсутствие публичного AyuGram iOS: https://docs.ayugram.one/downloads/.

База: https://github.com/TelegramMessenger/Telegram-iOS, commit указан в `upstream.lock.json`. Лицензии исходного Telegram и зависимостей сохраняются; при распространении производного клиента необходимо выполнить их условия. Ключи официальных клиентов не копируются.
